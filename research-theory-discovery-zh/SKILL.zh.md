# 研究理论发现

把任务当作开放式研究，而不是规格实现。目标是在优化实现之前，先发现真正的问题、正交的竞争解释、必要但缺失的理论结构，以及能决定胜负的实验。

**创造打开可行空间，数学检查闭合，实验决定去留。** 严谨验证不能替代结构发明；大胆构想也不能替代验收。先对齐用户真正要改善的能力，再选择值得验证的候选。

## 核心契约

1. 不要把用户提出的机制直接当作目标答案硬套，不拿搜索到的论文硬套作为理论支撑。
2. 明确区分不同可信度的信息：
   - 实验、日志或代码检查里已经看到的结果；
   - 从公式、定义或约束必然推出的结论；
   - 为了让理论解释实验而额外假定的条件；
   - 关于代码是否真的实现了某个机制的假定；
   - 对结果的解释；
   - 还没有证据支持的猜想。
3. 先生成预测，再看决定性实验或围绕它优化。
4. 实验结果检验的是整个理论包，不是只检验核心理论：

```text
核心理论 + 辅助假设 + 实现 + 优化 + 测量 -> 观测
```

5. 不要把实现成功本身当作机制成立的证明，也不要把单个坏结果直接当作核心理论死亡。
6. 不要自我批准重要主张。当可用独立 agent 或审查者时，把假设补充、实验计划、结论审核分别交给独立审查面；如果无法独立审核，必须标记为未审核。
7. 区分真实目标、验收指标和机制代理量。梯度一致、因果效应、分化、秩、能量或守恒成立，只能支撑各自的机制或数值主张。说明它们如何连接用户目标；能力是否改善要由目标对应的评估判断。
8. 分开发现与验收：允许尚无完整推导、但明确且可实现的设计直觉进入有界候选搜索。写清它新增什么能力、为何可能有用、成本和失败条件；验收时按证据强度限制结论。

## 当用户已有提案

先临时隔离用户提案。

从观测和约束独立重构问题，生成不依赖用户偏好机制的替代解释。然后再把用户提案作为候选之一放回来，用同一标准比较。

## 工作流

### 1. 建立证据账本

标注观测、约束、方程、不变量、失败实验、指标、便利假设、当前假设和未知项。需要外部验证的事实要明确标出。

先写一条目标契约：用户能力目标 → 主要验收量与评估场景 → 当前最强可复现基线 → 资源约束。生物类比、局部性、守恒等约束分别标为用户硬要求、数学必要条件或可调整的设计偏好。候选必须交代这些约束组合后，信息能否到达读出、监督能否改变相关计算、推理期是否拥有训练所用的信息。

对于长期研究，维护研究树，而不只是线性日志。每个重要假设、实现改动、实验族或结论都应挂到父节点上；如果未来发现某个基础节点有错，就能裁剪整棵依赖子树，而不是让那一团结论继续作为噪声干扰后续判断。

研究树应保存为 git 追踪的结构化文件，例如 `research_tree.json`。工作区中的树保持最新研究状态；用 git 历史实现可逆裁剪、回退和旧子树对比。

### 2. 重构问题

至少给出三个实质不同的问题表述。差异必须来自状态变量、状态空间几何、因果方向、时间尺度、对称性、可观测量、优化动力学、表示/检索关系或测量伪影等底层结构。

### 3. 做新奇假设搜索

生成 3 到 7 个竞争假设。它们必须在底层机制上尽量独立/正交，而不是同一个解释的不同说法。

优先寻找在以下方面不同的假设：状态变量、因果方向、几何、时间尺度、优化动力学、信息流路径、测量对象、表示/检索/压缩/控制的角色。

如果多个解释共享同一底层机制，把它们合并为同一假设族。

架构研究的候选应覆盖至少一种改变可行空间的方向：新增必要状态、改变因果信息路径、学习对象或时间关系，而非全都在旧结构中调参或诊断。若旧结构已可表达目标，说明依据并允许选择更小的修复。用户直觉是候选生成线索；将它转写为最强可检验版本，既保留创造力，也用同一标准比较。

### 4. 做必要性/数学闭合搜索

寻找为了让事实、公式和实验设置同时成立，理论中必须补上的对象或条件。

问：

- 哪些事实不能在没有额外结构时共存？
- 哪个变量、状态、对称性、耦合或尺度是由一致性强迫出来的？
- 哪些常数应该变成动力变量？
- 哪个外部训练操作可能本应属于模型内部动力学？
- 哪些反复补丁暗示缺失了共同机制？
- 哪个极限情况暴露出矛盾？

区分三种强度：**可能**、**有用**、**必要**。没有推导时，不要把“可能”或“有用”提升为“必要”。

在安排测量前检查搜索空间：可给出解析构造、反例、信息路径或明确的可学习对象作为可行性依据。若缺少完成目标的通路，下一步是最小结构修改；在结构里反复测量同一缺口不会生成该通路。可达性仅使候选值得探索，训练和任务验收决定它是否有效。

### 5. 推导理论自缚性预测

当从数学、物理类比、信息论、动力系统或跨领域一致性推出某个机制“理应生效”时，不要只写结论。必须写出理论绑定自己的条件：

- 什么条件下性能或机制指标必须提高；
- 什么条件下优势必须减弱、消失或反向；
- 什么观测说明“数学等价”没有被实现；
- 如果实验失败，冲突应优先落在哪些环节。

如果推不出能区分竞争假设的预测，明确说该想法目前只是设计直觉，不是理论。

设计直觉仍可提出有界工程试验：登记预期收益方向、最强基线、可识别的对照、停止条件与成本；没有推导依据时保留效应大小未知，避免编造数值门槛。将这种试验标为探索，理论主张另行接受机制证据检验。

### 6. 设计关键实验

优先设计能区分假设的实验，而不是只寻找提升的实验。

按目的选择实验：发现阶段可以直接测试一个结构候选是否改善真实目标；归因阶段用可识别对照区分原因。每个实验先写“收益 / 无收益 / 模糊”各将触发什么动作；若结果均导向同一动作，削减或合并测量，除非它是必要的数值、接口或安全验收。按决策价值和成本选实验，不以检查项数量代替进展。

保留可复现的最佳基线，候选围绕一个核心主张修改。允许系统协同改动，但要把必要的耦合改动登记为一个整体，解释其不可分性和对照方式；避免将多个独立修复同时叠加后，再靠局部探针寻找唯一病因。先修接口或数学矛盾，再用适足的联合训练判断能力。短窗口、冻结组件或单次更新只能回答其覆盖的局部问题。

使用“最少实验 / 最大信息量”约束：选择能产生最大决策信息量的最小实验集合。如果要优化的目标本来不在实验搜索空间里，应把它判为结构性设计问题，而不是继续调参。如果实验初始设定无法产生有信息量的结论，应及时止损并重新设计，而不是支付沉没成本。

优先级：解析证明或反例、带 ground truth 的最小系统、机制探针、受控消融、scaling/外推测试、广泛 benchmark。

封住“假胜利”路径：确认结果不是因为额外参数、训练预算、优化稳定性、数据泄漏、指标平均、隐藏递归、更深网络或多次 pass、事后挑选最好结果、实现不对称，或 baseline 走了另一条捷径。
对于开放性系统，还要确认：没有把可达性误报成发现、把序列化误报成生成、把手写 scaffold 误报成学习机制、把词表/codebook 泄漏误报成抽象能力，或把外部搜索/人工 patch 误报成自主谱系。

具体检查例子：

- scan/递归实现不能让当前 token 写后立刻读到自己；
- full-site active 不能和 ln_f-only active 当作同配置比较；
- 总 CE 不能替代 task/user/self/modality 分项；
- 如果 baseline 能靠 token 分布识别 modality，就不能把 modality acc 当作 Wmeta 成功；
- 如果收益来自更多参数或更长训练，不能直接归因给新机制。

### 7. 诊断理论-实验冲突

当预测和观测不一致时，沿理论包分解：

- 数学推导是否错；
- 理论是否超出适用域，适用于的边界条件是否真实可推广；
- 辅助假设是否为假；
- 实现是否真的实现理论对象；
- 优化是否进入相关区间；
- 指标是否对准预测量；
- baseline 是否有替代机制；
- 是否是统计或测量误差；
- 核心理论是否为假。

稳定、可复现的矛盾是理论发现入口。最小理论扩展不是为了保护原理论，而是为了定位理论包中缺失的环节，并寻找能同时解释原预测和反常结果的新结构。

### 8. 决定下一步

结尾必须落到一个动作：进入最小实现、先跑机制探针、推导缺失结果、收集另一种测量、比较替代假设、缩小适用域或放弃假设。给出决策规则和停止条件。

在投入高成本工作或给出强结论前，记录审核状态：假设由合作者式审查补充，实验计划由审批委员会式审查充分性和必要性，论据到结论由 reviewer 式审查。

复查本轮是否打开了新的可行空间、解决了明确实现矛盾，或改变了下一步决策。若只有描述增多，应缩小诊断、重构问题或进入一个有理由的候选实现，而非继续堆测量。允许结论保持未知，同时给出可执行的推进方向。

## 需要时读取

- 长研究会话、复杂理论冲突或需要例子时，读取 `references/research-protocol.zh.md`。
- 当研究陷入指标诊断、局部补丁或反复失败时，重点读取该文档的“发现与验收分工”部分；这些是方法论修正，不是某个模型病因的既定结论。
- 需要稳定输出格式时，读取 `references/output-schema.zh.md`。
- 需要可视化研究树时，把研究树写成 JSON，然后运行 `../harness/scripts/render_research_tree.py input.json output.html`。
- 想强制执行这套协议而不是仅仅依赖模型自觉遵守时，见 `../harness/README.md`。它提供三层强制：
  git hooks（拦截无效的 `research_tree.json` 或未记录的裁剪）、Claude Code hooks（每次编辑树时重新校验，
  树处于无效状态时阻止结束当前回合）、以及一个确定性编排的 `Workflow` 脚本
  （`../harness/workflows/research-cycle.js`，把假设生成、必要性审查、预测预注册、决策型实验计划，以及
  假胜利审计、独立审查，做成脚本控制流而不是可以跳过的步骤）。harness 是英文版和中文版共用的，
  是语言无关的代码和 hook，不是需要翻译的文字。

## 默认输出

除非用户要求其他格式，否则使用：

1. **研究状态**
2. **问题重构**
3. **竞争假设**
4. **必要性分析**
5. **预注册预测**
6. **关键实验**
7. **冲突与作弊路径**
8. **决策与停止条件**

长期研究还应包含 **研究树更新**。高成本实验或强结论还应包含 **审核状态**。
