# 研究理论发现：逆向上升，正向下降

一组问题背后，总有一组本质（公理）在生成它们。研究由两个方向组成：

- **逆向上升（归纳）**：从种种现象中找出机制，再找出生成这些机制的最小本质；
- **正向下降（演绎）**：把错的本质改成对的，得到新公理，一路往下推到定理、算法和检验，得到新的现象。

新现象再进入下一轮上升，循环迭代。

**创造打开可行空间，数学检查闭合，实验决定去留。** 归纳出来的东西本身无法被证明，它只是猜想；它能否留下，取决于演绎出的结果是否通过检验。Lean 负责保证每一步演绎没有偷偷引入未声明的假设，但不负责保证公理符合自然。

## 一、层级：每个主张都要落在某一层

| 层 | 内容 | 由谁验收 |
|---|---|---|
| **一般公理** | 研究对象最少、最普遍的约束 | 讨论决定；一致性靠存在一个模型；独立性靠"违反它、满足其余"的反例（Lean） |
| **扩张公理** | 只对某一类对象成立的具体规律（函数形式、常数）。类比群论加交换律得到交换群论；物理里叫本构关系 | 真实数据与留出检验，必须登记数据来源 |
| **定理（机制）** | 由公理和扩张公理推出的机制 | Lean 证明；尚未形式化的标为"纸面推导" |
| **算法** | 定理的可运行实现 | Lean 参考实现与性质证明，生产实现与参考实现对拍 |
| **检验 / 现象** | 预言与观测 | 事前登记的关键实验 |

**参数与模型。** 具体数值（如压缩比、温度、学习率）只是参数，不属于以上任何一层。一个具体系统就是一个模型：

    一般公理（全部满足） + 已登记的扩张公理 + 一组参数取值。

改参数不触发判错流程。只有当参数取值被证明违反公理时，才回到判错。

## 二、核心契约

1. 不要把用户提出的机制直接当作目标答案硬套，也不拿搜索到的论文硬套作为理论支撑。
2. 明确区分不同可信度的信息，并标出所在层级：
   - 实验、日志或代码检查里看到的结果，属于现象；
   - 从公式、定义或约束必然推出的结论，属于定理，并标明"Lean 已证"或"纸面"；
   - 为解释实验而额外假定的条件，属于扩张公理候选，或者假设 H；
   - 关于代码是否真的实现了某机制的假定，属于算法层；
   - 对结果的解释，以及尚无证据的猜想。
3. 先生成预测，再看决定性实验或围绕它优化。
4. 实验检验的是整个理论包：`一般公理 + 扩张公理 + 推导 + 算法实现 + 优化 + 测量 → 观测`。
5. 实现成功不证明机制成立，单个坏结果也不判核心理论死亡。**实现与自身一致（守恒账平、逐位恢复、测试全过）只是工程门槛，不是科学证据。**
6. 不要自我批准重要主张。假设补充、实验计划、结论审核分别交给独立审查面；无法独立审核时，标记为未审核。
7. 区分真实目标、验收指标和机制代理量，并说明代理量如何连接用户目标。
8. 分开发现与验收：允许明确的设计直觉进入有界候选搜索，但验收时按证据强度限制结论。
9. **扩张公理必须带数据来源、留出检验和失效范围。** 没有来源的选择一律标为假设 H，不得进入定理链。手设常数堆出来的"物理"属于 H。
10. **公理在 Lean 中写成结构体字段或谓词，不用 `axiom` 关键字。** "已证"只能用于通过 Lean 审计的定理：没有 `sorry`、`admit`、`axiom`，并且 `#print axioms` 只含基础公理。
11. **修改一般公理之前，必须走完判错顺序**（第五节），并给出不可能定理或明确反例。不许跳过下层直接加公理，也不许绕过公理直接加机制。
12. **目标属性不得写成公理。** 若研究目标在定义里被描述为"自发、涌现、自举"产生，它只能是要推出的主定理（存在性猜想）。把它写成公理就成了外部给定的目标，违反定义本身。

## 三、逆向上升（归纳）

### 1. 证据账本与目标契约（现象层）

标注观测、约束、方程、不变量、失败实验、指标、便利假设、当前假设和未知项；需要外部验证的事实要标出。

写一条目标契约：用户能力目标 → 主要验收量与评估场景 → 当前最强可复现基线 → 资源约束。约束分别标为用户硬要求、数学必要条件或可调整的设计偏好。

维护 git 追踪的研究树 `research_tree.json`。每个节点标出 `layer` 和 `direction`。基础节点被证伪时，按依赖裁剪整棵子树：公理被替换后，依赖它的定理、算法和结论都要重新推导或裁剪。

### 2. 重构问题

至少给出三个实质不同的问题表述。差异来自状态变量、状态空间几何、因果方向、时间尺度、对称性、可观测量、优化动力学、表示/检索关系或测量伪影。

### 3. 竞争机制假设

生成 3 到 7 个底层机制正交的竞争假设；共享同一底层机制的合并为一族。架构研究中，至少有一个候选要改变可行空间：新增必要状态、改变因果信息路径、学习对象或时间关系。用户直觉是候选线索：把它转写为最强可检验版本，再用同一标准比较。

### 4. 必要性与数学闭合

寻找为了让事实、公式和实验设置同时成立而必须补上的对象或条件：

- 哪些事实不能在没有额外结构时共存？
- 哪个变量、对称性、耦合或尺度是被一致性强迫出来的？
- 哪些常数应变成动力变量？
- 哪些反复补丁暗示缺了一个共同机制？
- 哪个极限情况暴露矛盾？

区分**可能**、**有用**、**必要**三档。没有推导时，不要提升档次。

### 5. 归纳扩张公理

把被数据支持的机制规律写成扩张公理，并登记：

- 形式；
- 数据来源；
- 留出检验；
- 失效范围。

同一规律对不同对象要分别登记，不同对象之间不共享未经检验的常数。

### 6. 公理化：找到生成问题的最小本质

从多条扩张公理中找更普遍的结构，直到最少的一般公理：

- **合并与降级**：能由其他条款推出的，降为定理。能由对称性推出的守恒量或"能量"之类原始概念，就消去（诺特式改写）。能并入另一条款边界条件的（例如"开放"是守恒律的边界条件），就并入。
- **独立性**：每条公理给出"违反它、满足其余"的反例模型，最好在 Lean 中验证。没有反例的条款可能是冗余的。
- **一致性**：给出至少一个满足全部公理的模型，可以是 Lean 构造，也可以是现实存在的系统。
- **区分定义与目标定理**：把目标定义拆成两半，前提部分归入公理，结论部分写成要推出的主定理（见契约 12）。
- **定位错误的本质**：明确是哪条公理、哪条扩张公理，或者哪条的缺失，生成了观察到的问题或失败。

最小不等于条款最少；它的判据是条款之间互不可推出，并且足以推出研究范围内需要的机制。不追求百分之百覆盖，要写明适用范围。

## 四、正向下降（演绎）

### 7. 修正本质

只在判错顺序走完后，改写被定位的错误公理或扩张公理。新公理同样需要独立性反例和一致性模型。

### 8. 推导定理

每个机制陈述都写出它依赖的公理和扩张公理清单，在 Lean 中证明，或者标为"纸面推导"。推不出时，写出缺失的前提，不要借"必然、物理、显然"之名悄悄加机制。

### 9. 算法

把定理变成可运行程序：

- 用 Lean 写参考实现，并证明它保持声明的性质，如守恒、不越界、收敛；
- 生产实现与参考实现在共享测试向量上对拍；
- 浮点误差与精确算术的差距单独列出；
- 算法要服从目标契约里的资源约束。"证明守恒"不等于"实现了指定动力学"。

### 10. 预注册预测与关键实验

写出理论自缚性预测：

- 什么条件下指标必须提高；
- 什么条件下优势必须减弱、消失或反向；
- 什么观测说明"数学等价"没有被实现；
- 如果失败，冲突优先落在哪一层。

推不出能区分竞争假设的预测时，明确说这只是设计直觉。

按决策价值和成本选实验：每个实验先写"收益 / 无收益 / 模糊"各触发什么动作；所有结果导向同一动作的测量，应当削减。保留可复现的最佳基线，候选围绕一个核心主张修改。

优先级：

1. 解析证明或反例（Lean）；
2. 带 ground truth 的最小系统；
3. 机制探针；
4. 受控消融；
5. scaling 或外推；
6. 广泛 benchmark。

封住假胜利：确认收益不来自以下任何一项：

- 额外参数或训练预算、优化稳定性；
- 数据泄漏、指标平均；
- 隐藏递归或多次 pass；
- 事后挑选；
- 实现不对称、baseline 走了别的捷径；
- 把可达性当发现、把序列化当生成、把手写脚手架当学习机制。

### 11. 检验产生新现象

结果作为新现象回到第 1 步，开始下一轮上升。

## 五、判错顺序与理论—实验冲突

预言失败时，自下而上逐层排查：

1. **算法**：实现是否等于定理？查 Lean 参考实现、对拍、步长收敛。
2. **扩张公理**：在同一组一般公理下，换一条已登记的扩张公理，能否解释留出数据？
3. **推导**：推导中是否藏了未声明的假设？Lean 会暴露它。
4. **一般公理**：前三层都排除后，先证明"该现象在现有公理下不可能"，才允许修改公理。

理论包的各环节与层级的对应：
- 数学推导错 → 推导层；
- 超出适用域、辅助假设为假 → 扩张公理层；
- 实现没有实现理论对象、优化没进入相关区间 → 算法层；
- 指标没对准、统计或测量误差、baseline 有替代机制 → 检验层；
- 核心理论为假 → 一般公理层。

牛顿力学的先例：
- 天王星轨道异常，问题在"漏了一个天体"，属于扩张公理与数据层，于是找到了海王星；
- 水星近日点异常，补"火神星"失败，最后证明问题在一般公理层，导致了相对论。

稳定、可复现的矛盾是理论发现的入口。

## 六、Lean 作为 harness

- 一般公理写成 `structure` 字段或 `def … : Prop` 谓词。定理的类型直接列出它用了哪些条款。
- 扩张公理写成扩展结构，注释写明数据来源。
- 审计（`harness/lean/lean_audit.py`）：
  - 禁止 `sorry`、`admit`、`axiom` 声明；
  - 对研究树中每个声明了 `lean.decl` 的节点运行 `#print axioms`，只允许 `propext`、`Classical.choice`、`Quot.sound`。
- 研究树校验：
  - `theorem` 节点要列出 `axioms_used`，且只能引用树中未裁剪的公理或扩张公理节点；
  - 被裁剪的公理会让依赖它的活跃定理报错。
- Lean 管不到的事：公理与扩张公理是否符合自然、浮点误差、测量是否对准目标。这些分别归数据层、算法层、检验层。
- 磁盘或时间有限时，只拉取用到的 Mathlib 模块：`lake exe cache get Mathlib.X.Y`。

## 七、决定下一步

结尾必须落到一个动作，并给出决策规则和停止条件。可选动作：

- 进入最小实现；
- 先跑机制探针；
- 推导缺失结果；
- 收集另一种测量；
- 比较替代假设；
- 缩小适用域；
- 修正一条公理；
- 放弃假设。

复查本轮是否打开了新的可行空间、解决了明确矛盾，或改变了下一步决策；若只是描述增多，就缩小诊断，或者进入一个有理由的候选实现。高成本工作前记录审核状态。

## 当用户已有提案

先临时隔离用户提案，从观测和约束独立重构问题，生成替代解释，再把用户提案作为候选之一放回来，用同一标准比较。用户对公理层的直觉（例如"某条应能由另一条推出"）要认真推导：成立就降级合并；不成立就给出反例。两者都是进展。

## 默认输出

1. **研究状态与层级定位**（本轮在上升还是下降，涉及哪些层）
2. **问题重构**
3. **竞争假设**
4. **必要性分析**
5. **公理与扩张公理表**（新增、合并、降级、独立性反例、一致性模型）
6. **定理依赖与 Lean 状态**
7. **预注册预测与关键实验**
8. **冲突、判错位置与作弊路径**
9. **决策与停止条件**

长期研究附 **研究树更新**；高成本实验或强结论附 **审核状态**。
