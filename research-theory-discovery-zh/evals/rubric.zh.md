# 深度评估 Rubric（仅用于 skill 迭代）

这是一个 28 分制的评分 rubric，用于对比 skill 不同版本的质量、排查多次运行中反复出现的失败模式、
或验证新的 prompt 族。不是为每次回答打分设计的——按回答逐次评分的成本不值得用在日常场景。
日常抽查单次普通回答请用 `quick-check.zh.md`；只有满足其"什么时候该升级"一节的条件时才回到这里。

每次运行每项打 0 到 2 分。

## 调用

- 0：用户明确要求时没有使用 skill。
- 1：提到了 skill，但基本忽略了工作流。
- 2：回答明显受 skill 工作流支配。

## 独立性

- 0：立刻发展或赞扬用户提案。
- 1：提到替代解释，但仍被用户提案锚定。
- 2：先重构问题并生成实质不同的替代解释，再比较。

## 新奇搜索

- 0：列出的是一组近似重复解释。
- 1：给出几个替代解释，但没有检查它们是否共享同一底层机制。
- 2：生成正交假设族，并把共享机制的解释合并。

## 必要性 / 数学闭合搜索

- 0：只把想法当作设计偏好或类比。
- 1：指出可能缺失的结构，但没有推导为什么它是被强迫出来的。
- 2：推导事实、方程和实验要同时成立必须满足什么，并把它转化为理论自缚性预测。

## 认识论标注

- 0：事实、假设、猜测混在一起。
- 1：标出了一些不确定性。
- 2：清晰区分观测、推论、辅助假设、实现假设和测量假设。

## 预测

- 0：只预测泛泛的提升。
- 1：给出可测试结果，但区分性不清。
- 2：给出可推导、可证伪、能区分竞争假设的预测。

## 实验设计

- 0：只提出宽泛 benchmark。
- 1：包含消融或探针。
- 2：设计了最小区分实验，包含混淆因素和决策规则。

## 最少实验信息量

- 0：增加实验或调参运行，但没有说明它会改变什么决策。
- 1：提到效率，但没有说明为什么该实验是最小且信息量高的。
- 2：使用必要的最少实验，通过丰富测量最大化信息量，并在设定无法测试主张时停止/重设计。

## 假胜利控制

- 0：直接把提升当作机制成功。
- 1：泛泛提到容量、泄漏或 baseline 问题。
- 2：构建具体假胜利检查表，覆盖容量、优化、泄漏、指标平均、实现不对称、baseline 绕行和事后筛选。

## 冲突诊断

- 0：直接宣布理论或实验错了。
- 1：列出几个可能原因。
- 2：围绕理论、假设、实现、优化、测量和 baseline 绕行构建结构化冲突树。

## 研究树记忆

- 0：把研究历史当作平铺的时间日志。
- 1：提到实验之间有依赖，但没有识别可裁剪子树。
- 2：把研究路径表示为树，包含父节点、依赖分支、失效条件和子树裁剪后果。

## 独立审查纪律

- 0：自我批准重要假设、实验计划或结论。
- 1：提到需要审核，但没有分离合作者、审批和 reviewer 角色。
- 2：把假设补充、实验审批、结论审核分配或标记为独立审查面，并明确标注未审核主张。

## 反补丁化

- 0：产生组件堆。
- 1：增加组件时有一些理由。
- 2：施加复杂度税，寻找最小理论扩展。

## 决策质量

- 0：没有具体下一步。
- 1：给出下一步。
- 2：给出下一步、决策规则和停止条件。

工作流是选择性的：不是每次回答都必须机械运行所有搜索方式。应按用户请求相关性评分；但显式机制主张、理论-实验冲突、架构发现类主张通常应覆盖新奇搜索、必要性/数学闭合搜索、预测、假胜利控制和冲突诊断。

目标分数：显式研究提示至少 24/28。
对于高风险机制主张、理论-实验冲突、架构发现类主张，目标至少 26/28。

负控提示不应隐式调用该 skill —— Codex 端通过 `agents/openai.yaml` 里的
`policy.allow_implicit_invocation: false` 强制；Claude Code 端通过 `SKILL.md` frontmatter 里的
`disable-model-invocation: true` 强制。
