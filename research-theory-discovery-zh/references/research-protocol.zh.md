# 扩展研究协议

## 目的

本文档扩展 `research-theory-discovery` 工作流，用于长研究会话。当问题包含多个实验、多个竞争理论，或一个持续演化的研究计划时读取。

## A. 证据类别

使用以下标签：

- **O - Observation / 观测：** 直接测量到或用户提供的结果。
- **K - Established knowledge / 已建立知识：** 有外部支持的结果或公认数学事实。
- **D - Deduction / 推论：** 从已声明前提推出的结论。
- **A - Auxiliary assumption / 辅助假设：** 连接理论与实验所需的假设。
- **I - Implementation assumption / 实现假设：** 关于代码或架构实际实现了什么的主张。
- **M - Measurement assumption / 测量假设：** 关于某个指标是否能检测相关现象的主张。
- **S - Speculation / 猜测：** 合理但尚未推导或观测到的想法。

研究回答不应让 S 或 A 静默伪装成 O 或 D。

## B. 盲重构

当用户给出偏好的机制时：

1. 不使用机制语言，重述观测。
2. 列出功能约束和数学约束。
3. 从至少三个不同概念家族生成替代解释。
4. 然后再比较用户偏好的机制。

这会降低对话锚定。它不能消除上下文中已有知识，所以应把它标为去偏过程，而不是真正的盲实验。

## C. 新奇假设搜索

假设空间探索应接近新奇搜索，而不是列出多个相似解释。

独立假设必须在底层结构上尽量正交。优先从这些维度制造差异：

- 状态变量不同；
- 因果方向不同；
- 状态空间几何不同；
- 时间尺度或更新频率不同；
- 优化动力学不同；
- 信息流路径不同；
- 测量对象不同；
- 表示、检索、压缩、控制的角色不同。

如果多个解释背后共享同一机制，应把它们合并为同一假设族，再寻找真正不同的替代族。

常见假设族包括：

- 用户机制假设；
- 更简单机制；
- 测量伪影；
- 优化失败；
- 实现没有实现理论对象；
- baseline 拥有替代路径；
- 问题定义本身不良；
- 另一种数学形式化。

## D. 理论强度阶梯

### 设计直觉

某个组件可能有帮助，并且有合理类比。

### 机制假设

声称某个明确的内部过程导致某个可观测效应。

### 受限理论

该机制在明确假设和给定适用域下产生可推导预测。

### 强理论

该机制压缩了多个观测，排除了替代解释，并通过新的区分性测试。

不要只因为 benchmark 提升就跳级。

## E. 独立审查面

不要让同一次推理同时发明、批准并验证一个高影响研究主张。

可用独立审查者时，使用三类审查面：

1. **核心假设的合作者审查。** 审查者应宽容地检查假设是否被表述成最强的自洽版本，补充可能支持它的机制，并指出什么会让它值得测试。这个角色不是敌对批评者。
2. **实验计划的审批委员会审查。** 审查者应判断实验是否充分、必要、最小、信息量高，并且动机足以消耗算力或时间。它应拒绝冗余、低信息量或结构设定错误的实验。
3. **结论的 reviewer 审查。** 审查者接收证据、协议和拟定结论，检查结论是否由证据推出，假胜利路径是否仍存在，以及研究树依赖关系是否让某些结论失效。

如果独立 agent 不可用，可以在内部执行同样检查，但必须标记为**未独立审核**并降低置信度。不要把内部自我批准的结论说成已经独立审查。

## F. 必要性/数学闭合搜索

必要性搜索不是普通头脑风暴，而是寻找为了让事实、公式和实验设置同时成立，理论中必须补上的对象或条件。

使用这些问题：

1. 哪些已知事实无法在没有额外结构时共存？
2. 哪个变量、对象、对称性、状态或耦合是由一致性强迫出来的？
3. 哪些常数应该成为动力变量？
4. 哪个外部训练操作可能本应属于模型内部动力学？
5. 哪些反复补丁暗示缺失了共同机制？
6. 哪个极限情况暴露出矛盾？
7. 哪个跨领域等价关系或第一性原理要求某个机制理应生效？

区分三种强度：

- **可能：** 与当前约束兼容。
- **有用：** 可能改善目标。
- **必要：** 若没有它，给定事实、公式或实验结构无法同时成立。

没有推导时，不要把可能或有用提升为必要。

## G. 理论自缚性预测

强预测不是“模型应该更好”，而是理论主动承担风险。

当从数学一致性、物理类比、信息论、动力系统或其他领域定理推出某个机制“理应生效”时，必须写出：

- 哪些前提必须成立；
- 哪些指标必须提升；
- 哪些条件下优势必须消失；
- 哪些结果说明等价关系没有被实现；
- 若失败，冲突优先落在哪些理论包环节。

例：若更新规则 `R <- R + beta * (v - Rk) k^T` 被解释为在线 LoRA/BRA 写入，那么数学上它等价于对 `||v - Rk||^2` 做一步梯度下降。由此可预言：在 key/value 对齐、步长足够、容量未满、读出路径有效时，重复写入同一内容应降低局部重构误差或预测误差。若实验不等价或性能变差，优先检查步长、归一化、key 空间、写入门、读出路径、优化和测量，而不是立刻判定在线 LoRA 理论错误。

## H. 预测质量

强预测应满足：

- 在决定性结果之前提出，
- 具体到可以错，
- 不同于最强替代解释，
- 对合理实现选择稳健，
- 附带测量流程，
- 绑定到推导。

弱预测只是说提议模型会更好。

## I. 关键实验矩阵

对每个实验，比较所有存活假设下的期望结果。

| 实验 | H1 | H2 | H3 | 主要混淆 | 决策规则 |
|---|---|---|---|---|---|

优先选择在不同假设下产生不同结果模式的实验。

## J. 最少实验 / 最大信息量约束

实验设计应最大化每次运行的信息量。压缩即智能：好的研究计划应该用最少实验提取最多决策相关信息。

使用这些规则：

1. 说明这个实验要改变哪个决策。
2. 检查被优化目标是否真的在实验搜索空间里。
3. 当一次实验能暴露多个机制变量时，优先丰富测量，而不是增加实验数量。
4. 如果所有可能结果都不会改变下一步决策，这个实验信息量低。
5. 如果设定在结构上无法测试该主张，及时止损并重新设计，而不是支付沉没成本。
6. 当失败模式是结构性的，不要把盲目调参当作研究。

例子：

- 如果声称记忆机制帮助跨 block 传递，同一个小实验应同时测 normal/zero/shuffle state、分 source loss、状态有效秩、写入/读出门、baseline 绕行，而不是先盲目长训。
- 如果目标行为在当前架构中没有任何路径能表达，调参无法验证该机制；这是搜索空间错误。
- 如果两个实验只是在冗余指标或表面变体上不同，应合并或删掉一个。

## K. 假胜利路径检查

实验设计必须主动封住“结果变好但机制没赢”的路径。

常见假胜利包括：

- **额外容量：** 新模型参数更多，提升来自容量而不是机制。
- **训练预算：** 新模型训练更久或看了更多数据。
- **优化改变：** 新模块让优化更容易，但机制本身未被使用。
- **数据泄漏：** 例如 scan/递归实现让当前 token 写后立刻读到自己。
- **指标平均：** 总 CE 掩盖 task/user/self/modality 的相反变化。
- **隐藏递归：** 一个模型多了循环、状态或多 pass，baseline 没有。
- **深度或 ensemble 效应：** 改进只是更深网络或多个路径投票。
- **事后筛选：** 跑很多配置后只报告最好结果。
- **实现不对称：** 例如 full-site active 与 ln_f-only active 被当作同配置比较。
- **baseline 绕行：** baseline 靠 token 分布、source ID、局部窗口或 prompt 模板直接解题。
- **可达性被误报成发现：** 证明搜索空间能表示某个结构、定理或架构，却被当成系统已经学会寻找或创造它。
- **序列化被误报成生成：** 模型能编码、解码、导入或 replay 某个对象，却被描述成自主发明了该对象。
- **手写 scaffold 替代学习机制：** 声称的学习机制实际由人工 builder、模板、课程、规则或特权 repair 逻辑完成。
- **教师或 oracle 泄漏：** controller 看到目标 builder、架构名、benchmark 标签、hidden-test 摘要、oracle edit 或事后轨迹，而这些本应在因果上下文之外。
- **词表泄漏：** 学到的 token、macro 或 codebook 条目夹带 benchmark 身份、source family、任务标签或人类架构名，而不是可复用机制。
- **搜索预算不匹配：** 某方法获得更多候选、verifier 调用、retry、beam width、mutation attempt、compile failure 容忍或人工干预。
- **宏先验未计费：** 方法使用预训练词表、架构库、compiler intrinsic、fused kernel 或 sidecar 参数，但没有计入描述长度、构建成本或 provenance。
- **编译器/内核捷径：** 收益来自对照表示不可用的特权 fused 实现、库函数、数值 backend 或隐藏状态。
- **压缩被误报成表达能力：** 更短描述、BPE/MDL gain 或 codebook 复用被直接说成更强函数表达能力，但没有分离构造或留出功能测试。
- **离线语料污染：** 预训练中用过的架构、轨迹、性能标签或 repair trace 以改名或近同构形式出现在“自主”评测中。
- **谱系断裂：** descendant 来自外部搜索或人工 patched artifact，而不是通过声明的因果 edit/commit 闭环产生。
- **产品指标过度外推：** 有用应用结果被当作完整机制证据，但更简单 baseline、固定架构或常规训练路线也能解释。

结论中必须说明哪些假胜利路径已经被封住，哪些仍是残余风险。

## L. 理论包冲突分解

当预测和观测不一致时，不要只问“理论错了还是实验错了？”检查：

1. 定理或推导是否正确陈述？
2. 实验是否实例化了它的前提？
3. 实现是否真正实现了提议对象？
4. 优化是否进入了相关解区间？
5. 指标是否观察到了预测量？
6. baseline 是否拥有替代路径？
7. 效应是否相对噪声太小？
8. 理论是否只在另一个尺度或极限成立？
9. 核心理论是否为假？

每个分支都需要一个区分测试和成本估计。

坏结果检验的是整个理论包，不是只检验核心理论：

```text
核心理论 + 辅助假设 + 实现 + 优化 + 测量 + baseline 关系 -> 观测
```

稳定、可复现的矛盾应被当作理论发现入口。最小理论扩展不是为了保护原理论，而是定位理论包中缺失的环节，并寻找能同时解释原预测和反常结果的新结构。

## M. 研究记忆

维护研究树，而不只是线性账本。研究路线会分叉：早期一个假设、代码路径、测量选择或数据构造，可能成为许多后续实验的根。如果未来发现这个根节点错误，依赖它的整棵子树都应作为一组被标记为无效或噪声。

使用渐进披露：树的顶层应保持紧凑，节点细节只记录决策相关信息。遵守最小描述 / 最大信息量原则。

研究树应保存为 git 追踪的结构化文件。推荐默认名：`research_tree.json`，放在研究 ledger 或项目报告附近。当前 checkout 的文件代表最新的活跃研究状态。Git 历史是可逆档案：裁剪子树、标记噪声、替换分支都应提交，这样旧版本仍可恢复。

用 git 来做：

- 当后续发现基础节点错误时回退；
- 对比被裁剪子树和替代分支；
- 把节点变化关联到 commit、run 或 report；
- 审计某个结论什么时候进入或离开可采信研究状态。

每个节点至少记录：

- 时间或 commit/run 引用；
- 动机；
- 做了什么或测试了什么；
- 结论；
- 未解决问题；
- 父节点；
- 依赖它的子节点；
- 失效条件。

维护一个账本，包含：

- 假设和版本，
- 带时间戳或 commit 引用的预测，
- 已完成测试，
- 已杀死假设，
- 未解决异常，
- 辅助假设变化，
- 每个研究决策的理由。

当某个节点失效时，不要静默删除后代。应把该节点和依赖子树标记为已裁剪、噪声、被替代，或仍有部分可复用。说明哪些结论不再可采信，哪些测量仍然有效。

如果从当前树中删除某个子树能提升清晰度，必须先记录裁剪原因并提交。删除本身可以接受，因为 git 让它可逆；未追踪的删除不可接受。

不要在看到结果后重写旧预测。只能追加修正。

## N. 发现与验收分工

创造打开可行空间，数学检查闭合，实验决定去留。三者各有职责。审计做得完整只能支持被审计的主张；结构创新的价值由用户目标下的收益决定。

### 先固定靶子

用一句话建立目标合同：用户要改善的能力、主要验收量和真实评估条件、最强可复现基线、资源约束。把用户硬约束、数学必要条件、设计偏好分开。机制因果、梯度一致性、能量稳定、有效秩和空间分化分别支持自己的局部主张；能力改进需要落到目标指标及部署条件。

### 生成候选时允许跳跃，验收时保持严格

用户直觉、跨领域类比与异常现象可以提供候选。先构造其最强、可实现、可证伪版本，再与其他候选公平比较。架构搜索应包含打开新可行空间的候选：改变状态、信息路径、学习对象或时序关系；已有结构足以表达目标时，可以有依据地保留它。

先检查输入信息能否到达决策、监督能否改变承重计算、推理时所需变量能否获得。若路径缺失，提出最小结构改变；若路径可达，进入优化与能力验证。可达性是尝试的依据，收益由真实目标检验。

设计直觉可以进入有成本与停止边界的探索性实现。记录它新增的表达能力、可行性依据、预期改善方向及失败条件。只有推导或独立先验证据支持时才给数值效应量；否则写明幅度未知。完整定理是强理论的标准，探索实现可以从更弱但明确的依据开始。

### 让测量服务下一步决策

每项测量预先写明三条分支：有收益时保留什么；无收益时删除或重设计什么；结果含混时补哪项区分检查。三个结果若都导向同一行动，应缩减该测量；必要的数值、接口或安全验收可以例外，并说明依据。按决策价值与成本选择检查，避免用审计项目数量代表研究进展。

发现阶段优先检验候选是否改善目标；归因阶段比较替代解释。保留最强基线，每个候选围绕一个核心主张。系统协同确实要求多处联动时，说明这些改变为何不可分、如何比较；用一串独立补丁保护原假设会失去可解释性。

### 把证据范围与结论范围对齐

数值恒等式、接口测试和短运行适合验证实现；冻结训练、单次更新和小预算实验适合局部诊断。能力主张需要真实数据、足够的联合训练、独立评估、学习曲线及停止依据。具体预算服从项目和用户规定，避免把某个项目的步数变成普适常数。

每轮应交付新增的可行结构、被修复的明确矛盾，或被证据改变的下一步决策。若只有描述越来越精细，缩减诊断并实现有依据的候选。允许未知，同时明确能推进目标的行动。

这些经验来自连续持存动力学研究中的反复失败，适用于研究方法；它们没有预先判定某个浴、读出、时间核或学习器必然正确。历史结果与代码路径应分别核验，避免把新方法写成旧结果已被证明的原因。
